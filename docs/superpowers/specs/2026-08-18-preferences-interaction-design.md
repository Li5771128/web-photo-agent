# RefTone 偏好设置交互设计

## 目标

在不接入后端的前提下，为 `design/preferences.html` 和 `design/workbench.html` 建立可跨页演示的偏好闭环：用户可以管理全局与场景偏好、在调色任务中确认采用的档案、查看偏好怎样改变建议，并由任务反馈明确写入新偏好。

## 范围与数据边界

- 使用浏览器 `localStorage` 保存演示数据；刷新和页面跳转后状态保留。
- 不接入账户、服务端、真实图像分析或真实 XMP 生成。
- 初次打开时写入现有示例偏好；提供“恢复示例数据”以便重新演示。
- 每次任务只采用全局偏好或一个场景档案，不能叠加多个场景档案。

## 数据模型

每条偏好包含：唯一标识、名称、强度（必须避免 / 通常喜欢 / 可尝试）、作用规则、来源任务、所属范围（全局或场景）、启用状态、当前版本和历史版本。

场景档案包含：场景名称、是否允许在任务中采用、偏好条目与更新时间。未创建档案不能在工作台采用；档案为空时可创建但不会产生约束。

回滚将某条偏好恢复到上一历史版本，并写入一条新的当前版本记录；不会删除历史，也不会改写已经生成的旧任务计划。

## 偏好页

- 分别展示全局偏好与场景档案中的条目，显示强度、来源、版本与启用状态。
- 场景档案可以创建、展开查看其条目，并通过开关设为可用或停用。
- 条目操作包括停用 / 启用、删除和回滚；无历史版本时回滚不可用。
- 恢复示例数据会覆盖本地演示状态，需明确确认。

## 工作台

### 采用档案

- 显示全局偏好和所有已创建且可用的场景档案。
- 用户选择“全局偏好”时，只应用全局已启用条目；选择场景时，应用该场景中已启用条目。
- 选择场景即表示用户确认本次采用该档案。参考图始终高于偏好：冲突的偏好被标为未采用，并说明原因。

### 个性化影响

调色计划前显示“本次偏好影响”清单，每项包含偏好、来源、规则结果和所影响参数。参数卡添加来源标签，标记为参考图驱动、偏好修正或偏好冲突未采用。

演示规则固定为：

- 避免高光过曝：收紧曝光最大建议值，并提示优先压低高光。
- 自然通透肤色：调整橙色 HSL 建议，并限制过高的色温。
- 暗部偏青胶片感：影响阴影色彩分级；若当前参考图要求暖暗部，则显示冲突且不采用。

### 写入偏好

- 用户对核心建议选择“采纳 / 修改后保留 / 不喜欢”后，出现“生成偏好候选”。
- 反馈项使用清晰的用户语言；“修改后保留”旁提供说明：认可调色方向，但自行调整了推荐值或做法。选中时强调该说明，避免用户误以为需要修改原始照片文件。
- 候选内容按反馈类型生成：直接采用可给出默认的正向候选；修改后采用必须先选择“偏强 / 偏弱 / 范围不合适”等修正方向；不采用必须先选择具体不喜欢的方面，且候选强度固定为“必须避免”。在完成该补充前，确认写入不可用。
- 候选表单允许选择保存位置（全局或已创建的场景）、强度和候选描述。
- 只有点击“确认写入偏好”才更新本地状态；工作台的影响清单和偏好页都立即反映新规则。

## 异常与反馈

- 若不存在可选场景档案，工作台保留全局偏好并解释原因。
- 删除操作需要浏览器确认，删除后不再影响新任务。
- 本地存储不可用时，页面仍可展示默认数据，并显示本次刷新后会重置的提示。

## 验证

1. 修改、停用、删除、回滚或创建场景档案后刷新页面，验证状态保留。
2. 在工作台切换全局和人像档案，验证影响清单与参数标签更新。
3. 选择一项反馈，生成候选并确认写入，验证它出现在相应档案且影响下一次计划。
4. 验证冲突偏好显示“参考图优先，未采用”。
5. 验证恢复示例数据后两个页面恢复初始状态。

## 非目标

- 不模拟或声称存在真实的用户账户、持久化服务、模型推理或参数校验器。
- 不在本次改动中重构页面整体视觉风格或引入前端框架。
