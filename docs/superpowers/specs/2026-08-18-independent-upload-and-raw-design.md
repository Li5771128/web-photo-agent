# A/B 独立异步上传与 RAW 目标图设计

日期：2026-08-18

## 目标

将现有一次性提交 A/B 两张图片的上传流程改为两个互不阻塞的自动上传通道。用户选择图片后立即开始上传，可以同时上传 A、B，分别查看真实传输进度，并在任何阶段只替换其中一张图片。两张图片确认可用后自动进入现有 Redis/Worker 图片内容理解流程。

本设计同时把普通图片大小上限提高至 30 MB，并为目标图 B 增加最大 40 MB 的 RAW 支持。上传百分比仅表示浏览器向服务器发送文件的进度；AI 图片内容理解只展示阶段状态，不显示百分比。

## 用户体验

### 独立自动上传

- A、B 卡片分别维护文件、缩略图、上传尝试、百分比、确认结果和错误状态。
- 选择文件后立即自动上传，不设置额外的整组提交按钮。
- A 上传时只禁用 A 的文件选择控件，B 仍可选择并上传；B 同理。
- A、B 同时上传时分别展示真实进度条和百分比。
- 百分比由浏览器上传进度事件中的已发送字节数计算，不通过定时器模拟增长。
- 有新的进度事件时立即刷新。连续 3 秒没有新事件时保持最后一个真实百分比，并显示“仍在上传”，不虚构进度。
- 浏览器发送达到 100% 后显示“服务器确认中”；只有服务端完成校验、存储和记录后才显示“上传成功”。
- A、B 均被服务器确认后自动入队。AI 阶段只显示“排队中”“图片内容理解中”“已完成”或明确错误。

### 缩略图

- JPG、PNG、WebP 在选择后通过本地 Object URL 立即显示缩略图。
- RAW 选择后立即显示包含格式、文件名和上传进度的占位卡，并提示：“RAW 文件需上传后生成预览，上传期间暂不显示缩略图。”
- RAW 上传完成并由 Worker 成功解码后，以无 EXIF、最长边不超过 1024px 的 JPEG 预览替换占位卡。
- Object URL 在换图、重新开始和组件卸载时释放。

### 换图与重新开始

- 每张卡片始终保留独立的“更换图片”入口。
- 上传期间换图会立即中止该卡片的旧请求，另一张图片不受影响，新文件选择后自动上传。
- AI 尚未开始时，换图只替换当前任务中对应角色的图片。
- AI 已开始时，选择新文件后先提示：“更换该图片会取消当前分析并重新开始。”用户确认后取消旧任务并创建新任务。
- 新任务在服务端复制未更换图片，只上传被更换的一侧。用户不需要重新选择或上传未更换图片。
- “重新开始”用于清空整个图片对。用户确认后，中止 A/B 未完成上传、取消旧任务、清空缩略图和进度；下一次选择文件时创建新任务。

## 文件类型与大小

| 角色 | 支持格式 | 最大大小 |
| --- | --- | ---: |
| 参考图 A | JPG、JPEG、PNG、WebP | 30 MB |
| 目标图 B | JPG、JPEG、PNG、WebP | 30 MB |
| 目标图 B | DNG、CR2、CR3、NEF、ARW、RAF、RW2、ORF | 40 MB |

- RAW 只允许作为目标图 B，不允许作为参考图 A。
- 服务端根据文件签名、允许的媒体类型及扩展名组合判断格式，不仅信任浏览器提供的 MIME 或文件名。
- 普通图片必须完成安全解码校验。RAW 在 Worker 中通过固定版本的 LibRaw/rawpy 完成解码校验和预览生成。
- RAW 解码失败只使 B 槽位进入可重试错误状态，不删除或重置已成功的 A。

## API 与状态模型

### 任务

首次选择 A 或 B 时，前端调用 `POST /api/tasks` 创建空任务，初始状态为 `collecting`。现有一次接收 A/B 的 multipart 接口被拆分，不再承担整组文件上传。

任务状态扩展为：

`collecting → queued → recognizing → vision_ready | vision_failed`

任一未终结状态都可以进入 `cancelled`；到期任务进入 `expired`。`cancelled` 和 `expired` 都是终结状态，Worker 不得将其恢复为其他状态。

### 上传尝试

每个任务创建 reference 和 target 两个上传槽位。每次选图先向对应槽位申请一个由服务器生成的上传尝试 ID，然后使用独立请求上传文件：

- `POST /api/tasks/{taskId}/assets/{role}/attempts`：创建当前上传尝试。
- `PUT /api/tasks/{taskId}/assets/{role}/attempts/{attemptId}`：上传并确认单个文件。

上传尝试 ID 防止已被浏览器中止的旧请求迟到后覆盖新文件。只有仍是槽位当前尝试的请求可以确认资产；过期尝试产生的临时对象必须删除，并返回明确的 `upload_superseded` 结果。

### 自动入队

每次资产确认后，服务端在数据库事务中检查 A/B 是否都已确认。最后完成的一侧通过条件更新将任务从 `collecting` 原子改为 `queued`。只有成功完成该状态转换的请求可以发送 Redis 作业，因此并行确认不能重复入队。

Redis 入队失败时任务进入 `queue_failed`，保留已确认的 A/B，允许安全重试入队，不要求重新上传文件。

### 取消与单侧替换

- `DELETE /api/tasks/{taskId}`：幂等取消任务并安排清理已上传对象。
- `POST /api/tasks/{taskId}/replacement`：在 AI 已开始后创建替代任务，请求体指定要替换的角色。

替代任务必须验证匿名会话归属。服务端将未更换资产复制到新任务专属对象键，并为新任务写入已确认资产记录；旧任务随后进入 `cancelled`。如果复制或新任务记录失败，不暴露半创建任务，并保留旧任务的可查询状态。

## 数据与并发约束

- 上传槽位记录当前尝试 ID、角色、状态及更新时间；任务和角色组合唯一。
- 每次成功上传使用唯一对象键，不原地覆盖旧对象。
- 资产确认以当前尝试 ID 作为条件写入。迟到、取消或已替换请求不能覆盖槽位。
- 任务从 `collecting` 到 `queued` 使用单条条件更新，保证最多一个并发请求取得入队资格。
- 取消操作幂等；重复取消返回相同终结状态。
- Worker 领取任务和写入结果都使用允许状态的条件更新。千问请求已经发出时无需强制中断，但返回结果必须在条件写入失败后丢弃。
- 替代任务复制未更换对象，而不是跨任务共享同一对象键，确保任一任务清理不会破坏另一任务。

## RAW 处理

- Worker 增加统一图像解码接口；普通图片由 Pillow 解码，RAW 由固定版本的 rawpy/LibRaw 解码。
- RAW 首先尝试提取可用的嵌入预览；不可用时以明确、固定的后处理参数生成 sRGB JPEG 预览。
- 发给千问的仍然只是纠正方向、去除 EXIF、最长边不超过 1024px 的 JPEG 派生图，并保持 `store: false`。
- RAW 原文件保留在临时对象存储中，供后续确定性测量读取；原文件不发送给千问，也不直接暴露给浏览器。
- RAW 的 EXIF 与动态范围线索属于后续 Issue 02 的测量输入。本功能只负责可靠解码、预览生成和格式错误反馈，不提前生成 Lightroom 参数。

## 错误处理与清理

- 单侧错误只更新对应上传槽位，另一侧已确认资产和缩略图保持可用。
- 文件过大、格式不允许、签名不符、普通图片无法解码及 RAW 无法解码分别返回可理解的错误码和用户文案。
- 浏览器主动中止上传不显示为系统故障；若由换图触发则直接进入新上传尝试。
- 取消或替换后的临时对象立即执行尽力删除；失败记录为待清理状态，由后续清理任务重试。
- 已取消任务的 Worker 迟到结果不能写入 `vision_analyses`，也不能把任务状态改回完成。
- 日志不得记录 API Key、Authorization、完整图片 Data URI、原始文件内容或可识别 EXIF。

## 测试策略

### 前端

- A 上传时 B 可选择并上传，B 上传时 A 同理。
- XHR 进度映射为独立真实百分比；3 秒无事件时保持原值并显示继续上传提示。
- 100% 后进入服务器确认状态，不能提前显示成功。
- 普通图片即时缩略图、RAW 占位提示及服务端预览替换。
- 上传中换图中止旧请求，AI 阶段换图触发确认和替代任务。
- 单侧错误、重试、重新开始及 Object URL 清理。

### API 与数据库

- 匿名会话不能访问、替换或取消其他会话的任务。
- A/B 并行确认只创建一个 Redis 作业。
- 旧上传尝试迟到时不能覆盖新尝试，并清理自己的对象。
- 普通图片 30 MB、RAW 40 MB 的边界及超限行为。
- RAW 仅能用于 B，并覆盖全部首批扩展名、签名不匹配和损坏文件。
- AI 阶段单侧替换复制未更换对象，失败时不留下可用的半创建任务。
- 取消幂等，取消后的 Worker 完成写入被拒绝。

### Worker

- 每种首批 RAW 格式至少有一个最小合法夹具或经授权的测试样本。
- 嵌入预览与 RAW 后处理回退路径都生成受限尺寸、无 EXIF 的 JPEG。
- 损坏或不支持的 RAW 得到稳定错误码。
- 取消发生在领取前、读取对象后及模型返回后三个时点时，任务都不能被恢复。

### 手动验证

- 使用两张接近 30 MB 的普通图片并行上传。
- 使用接近 40 MB 的 RAW 作为 B，验证占位提示、上传进度、服务端缩略图和内容理解。
- 在浏览器网络限速下快速连续替换 A、B，并验证页面持续响应且最终结果只对应最后选择的图片。

## 范围外

- 断点续传、分片上传和跨页面恢复正在进行的上传。
- RAW 作为参考图 A。
- 浏览器本地解码 RAW。
- 为 AI 阶段估算或显示百分比。
- 在本项中实现确定性直方图、色彩测量或 Lightroom 参数计划；这些仍属于 Issue 02。
