# 分析结果页与 Lightroom 参数计划设计

日期：2026-08-19  
状态：已确认  
目标分支：`test`

## 1. 背景与目标

项目已经具备独立上传 A/B 图片、手动确认分析、RAW 安全预览、千问视觉理解和确定性图像测量。当前缺口是：用户无法在正式结果界面查看完整测量数据，也没有经过安全约束的 Lightroom 参数计划。

本阶段参考 `design/mvp-flow-workbench.html` 与 `DESIGN.md`，完成以下目标：

1. 先提供可查看现有测量和识图结果的正式结果页。
2. 将测量协议升级到 Schema v2，增加真实 RGB 直方图。
3. 在视觉理解之后增加一次独立的千问参数规划调用。
4. 使用本地确定性校验器过滤和约束模型草案，仅展示安全计划。
5. 保持单页工作流和既有视觉语言，不提前暴露尚未实现的 XMP 或历史修订功能。

## 2. 非目标

- 本阶段不生成或下载 XMP。
- 本阶段不实现参数计划的历史版本与人工修订。
- 不显示分析百分比或模拟进度。
- 不把模型输出直接当作可执行 Lightroom 配置。
- 不从确定性冷暖指标推断具体色温 Kelvin 值。
- 不修改或伪造历史 Measurement Schema v1 数据。

## 3. 用户流程与任务状态

页面保持单路由三阶段结构：

1. 上传图片
2. 正在分析
3. 查看结果

上传阶段继续显示真实上传百分比。用户点击“确认分析”后进入分析阶段，只展示当前文字状态：

```text
queued -> measuring -> recognizing -> planning -> validating -> ready
```

- `measuring`：执行确定性测量并生成/确认安全预览。
- `recognizing`：首次千问调用，生成结构化视觉语义结果。
- `planning`：第二次千问调用，根据经过清洗的测量和语义数据生成参数草案。
- `validating`：本地确定性校验参数草案。
- `ready`：完整结果可展示。

任一阶段失败时，API 保留此前已经完成的数据，并返回明确的失败阶段。页面不得把部分结果描述为完整分析。重试规划时复用已有测量和视觉结果，不重复上传、测量或识图。

## 4. 处理架构

### 4.1 Measurement Schema v2

Schema v2 保留 v1 的确定性读数，并为每张图新增真实 RGB 直方图：

- 红、绿、蓝三个通道。
- 固定数量、固定边界的等宽分箱。
- 同时保存分箱计数所需的样本总量与归一化结果，确保前端绘制可复现。
- 算法版本显式记录，避免未来实现变化造成静默差异。

历史 v1 记录仍按 v1 读取；只有重新测量才生成 v2，不能在缺少原始计算结果时伪装成 v2。

### 4.2 两次模型调用

第一次调用沿用现有视觉理解职责，只输出经过 Schema 校验的语义数据。

第二次调用只接收：

- 清洗后的 Measurement Schema v2 读数和 A/B 差异。
- 已通过 Schema 校验的视觉语义 JSON。
- Lightroom 参数白名单、输出 Schema 与必要约束。

第二次调用不接收原图、EXIF、文件路径、存储地址或其他未过滤元数据。模型只负责生成结构化草案、解释和风格总结，不负责最终安全裁决。

### 4.3 本地参数校验

模型草案进入本地确定性校验器。校验器负责：

- 拒绝未知参数和自由文本操作指令。
- 校验类型、单位、数值和分组。
- 将有效项目限制在 8–12 项；不足时不虚构参数，整体标记为不可用并给出可重试原因。
- 按“基础校正 -> 风格塑造 -> 可选微调”稳定排序。
- 同时应用 Lightroom 合法范围与项目定义的更窄安全范围。
- 对 JPEG 使用比 RAW 更保守的曝光、白平衡和色彩范围。
- 根据亮部/暗部裁切、动态范围和肤色风险进一步收紧范围。
- 对轻微越界且语义明确的值进行可审计钳制；对大幅越界、单位错误或风险冲突直接拒绝。
- 为每次钳制或拒绝记录机器可读原因。

只有通过校验的计划可以成为最终结果并展示给用户。

## 5. 结果页信息架构

结果页遵循现有 MVP 工作台的企业工具风格，按以下顺序展示：

1. 风格名称、简短总结和匹配可行性。
2. A/B 安全预览。
3. A、B 两个独立的 RGB 直方图面板。
4. 全部确定性读数。
5. A/B 差异与建议调整方向。
6. Lightroom 参数计划。
7. 风险、停止条件和不可迁移因素。

详细读数默认全部可见，不增加展开按钮。读数至少包括：

- 线性亮度均值、标准差、P05、P50、P95。
- 阴影、高光、黑场、白场裁切比例。
- RMS 对比度和有效动态范围。
- HSL 饱和度。
- 色相分布和主色。
- 冷暖与偏绿/偏洋红指数。
- 边缘活跃度。
- RAW 位深、黑场和白场线索（如可用）。

RGB 直方图采用 A/B 分面展示，不在同一坐标系叠加六条曲线。这样既能保持真实数据，也避免视觉混乱。

参数卡片按三个阶段分组，每张卡展示：

- 参数名称与单位。
- 建议起始值。
- 安全范围。
- 调整原因。
- 预期效果。
- 风险和停止条件。

未实现的 XMP 下载与历史修订入口不展示为可用按钮，也不以禁用控件误导用户。

## 6. 可行性计算

可行性不直接采用模型自报分数。系统按以下方式生成：

1. 根据确定性测量差异计算基础匹配度。
2. 从已验证的语义字段中提取场景、主体和光线不一致因素。
3. 使用固定、有限的扣分规则生成 0–100 分和低/中/高等级。
4. 同时展示主要扣分原因，避免只有一个缺乏解释的精确数字。

语义差异参与扣分，但公式和权重由本地版本化逻辑控制。模型不能任意决定最终分数。

## 7. 参数数据契约

最终计划包含：

- 风格名称与摘要。
- 可行性分数、等级和原因。
- 有序的参数项目。
- 每项的参数键、展示名、分组、起始值、安全上下界、单位、原因、效果、风险和停止条件。
- 目标文件类型以及影响校验的风险标记。
- 计划 Schema、模型、Prompt 和校验器版本。

初始参数白名单覆盖高价值调整，不要求每次全部使用：

- 基础校正：曝光、对比度、高光、阴影、白色色阶、黑色色阶、色温、色调。
- 风格塑造：纹理、清晰度、去朦胧、自然饱和度、饱和度、结构化曲线或受限 HSL 调整。
- 可选微调：受限颜色分级或暗角。

具体数值范围由独立版本化模块定义，Prompt 中的提示范围不能替代服务端校验范围。

## 8. 持久化与 API

### 8.1 测量数据

现有测量记录继续保存 Schema 版本。v2 在原有结构中增加直方图字段，不改变 v1 的解释方式。

### 8.2 Lightroom 计划

新增 `lightroom_plans` 持久化结构，至少保存：

- 任务标识与版本。
- 模型草案。
- 最终安全计划。
- 校验状态与拒绝/钳制原因。
- 模型、Prompt、Schema、校验器版本。
- 创建与更新时间。

原始模型草案只用于审计和排错，不直接返回为用户可执行计划。

### 8.3 结果 API

结果 API 返回：

- 当前任务阶段和失败阶段。
- 已完成的部分结果及其 Schema 版本。
- A/B 安全预览地址。
- 确定性测量、RGB 直方图和 A/B 比较。
- 已验证视觉报告。
- 仅在验证通过后返回最终 Lightroom 计划。

前端必须依据明确字段判断结果是否完整，不通过猜测字段存在与否推断状态。

## 9. 错误处理与隐私

- 模型返回非 JSON、未知参数、单位错误或无法校验内容时，规划阶段失败并允许重试。
- 数据库写入使用事务或等价原子边界，不能留下状态为 `ready` 但计划缺失的任务。
- 日志不得记录图片二进制、EXIF、API Key 或完整未过滤模型输入。
- 千问配置继续通过环境变量提供，密钥不进入源码、日志或数据库。
- 第二次调用与首次视觉调用一样显式配置供应商、模型和版本。

## 10. 测试与验收

### 10.1 自动测试

- 使用纯色、梯度和已知像素分布的合成图片验证 RGB 分箱、归一化与确定性。
- 验证 Measurement Schema v1/v2 的读取兼容性。
- 验证规划适配器请求不包含原图、EXIF、路径和未过滤字段。
- 使用模拟模型响应验证正常 JSON、异常 JSON、未知参数、单位错误和越界值。
- 验证参数白名单、项目数量、排序、RAW/JPEG 差异和风险收紧。
- 验证钳制与拒绝原因可审计。
- 验证任务完整状态流、失败阶段、部分结果和规划重试。
- 运行 Worker 单元测试、Web 类型检查与生产构建。

自动测试不调用真实千问服务，避免不稳定性和额度消耗。

### 10.2 手动验收

- 上传常规 A 图与 JPEG B 图，确认三阶段页面切换和结果数据完整。
- 上传 RAW B 图，确认预览、RAW 线索和更宽但仍受控的计划范围。
- 检查 A/B 直方图是否来自真实图像且可辨认。
- 检查详细读数默认展示，无需额外点击。
- 检查参数数量、顺序、解释、安全范围与停止条件。
- 模拟规划失败，确认此前的测量和视觉结果仍保留且可重试。

## 11. 实施顺序

1. 结果页骨架：复用现有数据，先完成三阶段页面和测量/视觉结果展示。
2. Measurement Schema v2：计算、持久化并展示真实 RGB 直方图。
3. 参数规划：接入第二次千问调用和独立 Prompt/Schema。
4. 确定性校验：实现白名单、范围、格式和风险约束。
5. 数据持久化与状态：新增计划记录、完整状态流和重试边界。
6. 集成结果页：展示最终计划、可行性和风险。
7. 完成自动测试与手动验收说明。

## 12. 关键取舍

- 采用两次模型调用，增加一次调用成本，换取职责隔离、可重试性和更稳定的结构化计划。
- 先生成页面骨架，使已完成的测量和识图能力立即可见，再逐步填充后续计划。
- 使用本地确定性校验而非仅靠 Prompt，避免模型输出直接成为危险或无效参数。
- RGB 直方图采用 A/B 分面而非六曲线叠加，牺牲少量直接重叠比较，换取更好的可读性。
- 不提前展示未实现功能，保证界面上的每个可操作入口都真实可用。
