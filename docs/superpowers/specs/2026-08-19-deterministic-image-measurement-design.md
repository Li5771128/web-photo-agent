# 确定性图像测量设计

日期：2026-08-19

## 目标与边界

为每个已确认的参考图 A 和目标图 B 生成本地、可复现、版本化的数值测量，并计算明确的 A/B 差异。这些结果是后续 Lightroom 参数规划的事实输入，不能由千问估算或覆盖。

本阶段交付测量引擎、持久化、任务状态与 API 返回，不在网页展示具体测量数值。用户界面只增加“图像测量中”阶段文案；测量结果将在 Lightroom 参数计划阶段统一解释和展示。

## 方案

使用 Pillow/rawpy 负责解码和方向处理，使用固定版本 NumPy 对统一采样图执行向量化统计。与引入 OpenCV 或 scikit-image 相比，该方案保持较小依赖面，同时提供稳定、易测试的分位数、直方图和差异计算。

所有算法参数、颜色转换、阈值和输出字段都固定在测量 Schema 版本中。相同输入、依赖版本和 Schema 版本必须得到相同结果；输出浮点数统一舍入，禁止出现 NaN 或 Infinity。

## 解码与标准化

### 普通图片

- 使用 Pillow 完整解码并应用 EXIF Orientation。
- 统一转换为 sRGB RGB 数据；透明区域在白色背景上合成。
- 不放大图片，最长边缩小至 1024 像素后参与测量，以限制内存和计算时间。
- ICC 无法可靠转换时使用明确错误，不默默声称完成准确测量。

### RAW

- 使用固定版本 rawpy/LibRaw 读取原始文件。
- 颜色统计使用固定后处理参数生成 sRGB 数据：相机白平衡、关闭自动增亮、固定输出位深和颜色空间。
- RAW 动态范围线索从 LibRaw 可用的非识别性元数据读取，例如原始位深、白位和黑位范围；缺失字段返回 `null`，不猜测。
- 不持久化 GPS、相机序列号、作者、版权、拍摄时间或其他可识别 EXIF。

## 单图测量 Schema

每个角色输出以下版本化数据：

- `source`：`standard` 或 `raw`、方向纠正后的宽高、长宽比和采样尺寸。
- `luminance`：线性相对亮度的 mean、standard deviation、P05、P50、P95。
- `tonal_regions`：阴影、高光、近黑裁切和近白裁切像素占比。
- `contrast`：RMS 对比度和 P95-P05 有效明暗范围。
- `saturation`：HSL 饱和度的 mean、P50 和 P95。
- `hue_histogram`：12 个固定 30° 色相区间的归一化占比；低饱和像素不参与色相分布。
- `dominant_colors`：最多 5 个确定性量化的 sRGB 颜色及各自占比；顺序按占比降序，再按颜色值稳定排序。
- `color_cast`：范围为 `[-1, 1]` 的 warmth 与 green-magenta 指数。这些是相对倾向，不标记为 Kelvin 或绝对白平衡。
- `edge_activity`：固定灰度梯度阈值下的边缘像素占比，只作为后续裁切和细节风险线索，不单独声称检测到主体裁切。
- `raw_clues`：仅 RAW 可用的位深、黑位和白位线索；普通图片为 `null`。

阈值和计算公式由代码常量定义并记录在 `schema_version = 1` 中。所有比例范围为 `[0, 1]`，色相直方图在存在有效彩色像素时总和为 1。

## A/B 差异 Schema

差异由确定性代码从两份单图测量计算，不重新读取图片。至少包含：

- 中间亮度、有效明暗范围和 RMS 对比度差值；
- 平均饱和度差值；
- warmth 与 green-magenta 差值；
- 阴影、高光、黑位和白位裁切占比差值；
- 参考图与目标图主导色相分布的固定距离；
- 每项差异的方向枚举：`increase`、`decrease` 或 `similar`。

差值定义统一为 `reference - target`，即正值表示目标图需要增加该维度才能接近参考图。`similar` 使用每项固定容差，容差随 Schema 版本管理。

## 持久化与 API

新增 `image_measurements` 表：

- `task_id`：主键并外键关联临时任务，任务删除时级联删除；
- `schema_version`：当前为 1；
- `reference_result`、`target_result`、`comparison_result`：JSONB；
- `completed_at`：完成时间。

Worker 在同一数据库事务中写入三组结果，避免 API 读取到只有 A 或 B 的半完成测量。重复执行使用 upsert 覆盖同一任务与 Schema 版本的结果。

任务查询 API 在存在结果时返回：

```json
{
  "measurements": {
    "schemaVersion": 1,
    "reference": {},
    "target": {},
    "comparison": {},
    "completedAt": "..."
  }
}
```

本阶段前端不渲染这些字段。

## Worker 流程与状态

任务状态扩展为：

`queued → measuring → recognizing → vision_ready`

1. Worker 原子领取 `queued` 任务并进入 `measuring`。
2. 读取原始 A/B，在本地分别测量并计算差异。
3. 仅当任务仍为 `measuring` 时，原子保存结果并进入 `recognizing`。
4. 随后生成安全预览并调用千问；视觉结果仍按现有条件写入。

测量先于 API Key 检查。即使千问 Key 缺失或服务调用失败，已完成测量仍保留并由 API 返回。

测量失败时任务进入 `measurement_failed`，使用稳定错误码区分解码、颜色转换、计算和持久化错误。失败任务不能继续调用千问。取消或过期任务的迟到测量必须被丢弃。

RAW 确认前预览与本次测量共享底层解码工具，但保持不同的业务接口：预览返回安全 JPEG，测量返回结构化数据。两者不得通过模型输出互相替代。

## 模块边界

- `images`：隐藏普通图片与 RAW 解码，提供面向预览和测量的标准化图像入口。
- `measurements`：只接收标准化像素和非识别性 RAW 线索，返回版本化单图结果与 A/B 比较结果；不访问数据库、对象存储或千问。
- `repository`：负责测量结果的条件写入、状态迁移与 API 查询所需的数据持久化。
- Worker 编排器：负责读取资产、调用测量、保存结果，再进入现有视觉识别阶段。

后续 Lightroom 规划模块只依赖测量 Schema，不依赖 NumPy、Pillow、rawpy 或图像原始字节。

## 错误、安全与资源约束

- 测量输出不得包含原图字节、文件路径、完整 EXIF 或可识别元数据。
- 单图解码与采样限制最大像素数和最长边，避免压缩炸弹或异常 RAW 占满内存。
- 所有数值在写入前执行有限值、范围和结构校验；无效结果不得持久化。
- 日志只记录任务 ID、阶段和稳定错误码，不记录像素、EXIF、对象内容或凭证。
- 任务取消、替换或过期后，测量写入的条件更新必须失败，Worker 丢弃内存结果。

## 测试策略

### 测量单元测试

使用代码生成的无敏感合成图片验证：

- 全黑、全白、50% 灰和黑白分区的亮度、分位数与裁切占比；
- 低对比和高对比图片的方向；
- 灰度与纯色图片的饱和度；
- 暖色与冷色、绿色与洋红图片的倾向方向；
- 固定色块比例的色相直方图与主色排序；
- 平坦图与棋盘图的边缘活动度；
- A/B comparison 的差值符号和 `increase`、`decrease`、`similar`；
- 透明图合成、EXIF 方向和超长图片下采样；
- 所有输出数值有限、范围合法且同一输入重复结果一致。

### RAW 与编排测试

- 通过 mock 的 rawpy 数据验证固定后处理参数和 RAW 非识别性线索映射。
- 损坏 RAW 和普通图片返回稳定测量错误。
- Repository 仅在 `measuring` 状态保存完整结果并进入 `recognizing`。
- 已取消任务拒绝测量写入，且不调用千问。
- 千问缺 Key 或失败时，已保存测量仍存在。

### 实际执行

- 运行 Worker 全部单元测试。
- 执行数据库迁移并确认 `image_measurements` 表存在。
- 构建 Worker 镜像。
- 运行不调用千问的测量冒烟流程，验证任务包含 A/B/comparison 三组结果。

真实相机 RAW 的跨格式测量准确度仍需授权样本人工验证；没有真实样本时不得声称八种 RAW 均已验证。

## 范围外

- 测量结果的用户界面、图表或解释文案。
- Lightroom 参数草案、数值安全校验和匹配可行度评分。
- 精确相关色温、相机色彩科学反演、场景照度或绝对动态范围档数。
- 人脸、主体、语义分割和自动裁切判断；这些只能由现有语义上下文提供风险线索。
- XMP 导出和同会话二次微调。
