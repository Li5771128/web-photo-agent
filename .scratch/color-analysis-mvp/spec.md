# 调色分析 MVP

Status: ready-for-agent

Archive: partial — 核心上传、测量、规划和结果页已完成；XMP、二次微调与到期清理见 `archive.md`。

## Problem Statement

摄影用户看到喜欢的参考图时，难以将其中可迁移的明暗与色彩特征转化为适合自己目标照片的 Lightroom 调整步骤。现有滤镜通常不可解释且不适配素材；一键修图又削弱用户控制感。现有产品定义中的账户、审美偏好档案、版本历史和跨任务个性化，不能验证这一核心问题，反而扩大了状态管理、隐私与测试范围。

## Solution

提供匿名的一次性调色分析任务。用户上传一张参考图 A 与一张目标照片 B，系统分析 A 的风格和 A/B 的差异，输出有解释、有安全范围、按 Lightroom 编辑顺序排列的参数计划。用户在 Lightroom 中手动调整，并可在同一临时会话上传调整后的 JPG 预览以继续微调。

已校验的结构化参数计划是唯一事实来源。用户可选择将该计划导出为确定性生成的 Lightroom XMP 预设；导出只是辅助操作，不能替代或阻塞参数卡的核心手动调色路径。

## User Stories

1. 作为 Lightroom 摄影爱好者，我希望上传一张参考图和一张目标照片，以便无需创建账户即可获得有针对性的调色分析。
2. 作为 Lightroom 摄影爱好者，我希望系统校验每个上传文件的格式、大小和可解码性，以便在必须替换文件时立即得知。
3. 作为 RAW 用户，我希望分析使用可用的 EXIF 和动态范围线索，以便建议能反映 RAW 更大的调整空间。
4. 作为 JPEG、PNG 或 WebP 用户，我希望获得保守的高风险调整范围和明确警告，以免将已输出图片误认为可恢复的 RAW 文件。
5. 作为用户，我希望获得包含简短风格摘要、色板、明暗分布、对比度、饱和度和色彩倾向的参考风格报告，以便理解要复现的特征。
6. 作为用户，我希望报告区分可迁移的调色特征与构图、光线和场景特征，以便建立合理预期。
7. 作为用户，我希望获得 A/B 匹配可行度评估，以便了解目标照片何时无法接近参考图。
8. 作为用户，我希望 Lightroom 计划按基础校正、风格塑形和可选微调排序，以便可靠地执行。
9. 作为用户，我希望每项建议都包含面板、数值或范围、原因、预期效果和风险，以便始终掌控编辑过程。
10. 作为用户，我希望在检测到裁切、肤色风险或素材调整空间有限时，建议会自动收紧，以便避免破坏性编辑。
11. 作为用户，我希望能在 Lightroom 中手动输入显示的参数，以便产品帮助我学习，而不是悄悄修改照片。
12. 作为用户，我希望在当前会话上传调整后的 JPG 预览图，以便基于上一轮计划和可见结果获得下一轮微调方案。
13. 作为用户，我希望后续方案保留相同的解释和安全约束，以便修改建议仍然可执行。
14. 作为用户，我希望可以选择下载由已校验计划生成的 XMP 预设，以便在需要时将其作为 Lightroom 的起点。
15. 作为用户，我希望 XMP 导出明确说明它只是起始配方，仍可能需要少量手动调整，以免期待像素级匹配。
16. 作为用户，我希望 XMP 导出失败时参数卡仍可使用，以便可选导出失败不会阻塞核心流程。
17. 作为注重隐私的用户，我希望处理完成或临时会话结束时删除原始上传文件和可识别 EXIF，以便服务不会默认保留我的照片。
18. 作为用户，我不希望创建或管理偏好档案，以便首次任务始终聚焦于当前选定的 A/B 图片对。

## Implementation Decisions

- MVP 是匿名、临时的单任务体验：不提供邮箱登录、账户、项目历史、持久化报告库、偏好档案或跨任务个性化。
- 每个任务固定包含一张参考图 A 和一张目标图 B。支持 JPG、JPEG、PNG、WebP；当处理链支持时，B 还可为 RAW。
- 语义视觉识别使用阿里云百炼 OpenAI 兼容 Responses API，默认模型为 `qwen3.7-max`。Worker 只发送纠正方向、移除 EXIF、长边不超过 1024px、JPEG 质量 80 的 A/B 派生预览，并设置 `store: false`；不向模型发送原始分辨率图片或 RAW。
- 千问识图只负责场景、主体、人物与肤色、光线、可迁移特征和匹配限制等语义上下文。其输出不能冒充亮度、直方图、色彩或动态范围的确定性测量，也不能绕过后续参数安全校验。
- 千问 Base URL、模型和凭证均由环境变量注入。`DASHSCOPE_API_KEY` 只填写在未提交的 `.env` 中，`.env.example` 必须保持空值。
- 分析流程限定为：确定性图像测量、风格解释、确定性 A/B 差异测量、受约束的结构化参数草案、参数校验和面向用户的渲染。
- 确定性图像测量提供亮度分布、明暗区域占比、主色、色相/饱和度/明度分布、色温倾向、对比度、裁切风险，以及可用时的 RAW 专属元数据和动态范围线索。
- 参数计划采用 Lightroom 优先的术语，且始终遵循“基础校正、风格塑形、可选微调”的顺序。每项调整包含面板、参数、推荐值或范围、理由、预期效果和风险。
- 参数校验器负责数值边界和格式相关的风险限制；在展示或导出任何计划前收紧或拒绝不安全建议。
- 核心对外行为是参数计划路径：有效 A/B 输入产生可手动在 Lightroom 中执行的可行计划，或明确说明限制的计划。这是唯一且最高层的测试缝隙。
- XMP 导出是已校验计划的次级分支，仅在用户明确选择后执行，只导出适用的全局调整，并由确定性代码生成，而非由模型直接生成文件文本。
- 导出的 XMP 可包含基础明暗、白平衡、曲线、颜色混合、色彩分级和全局效果；不包含裁切、镜头校正、蒙版、修复或其他依赖具体照片的调整。
- 同一会话中上传 JPG 预览可开启新的微调轮次。该轮次使用上一份已校验计划和新的图像测量结果，不创建长期用户档案或保存偏好。
- 处理错误必须说明失败发生在上传、分析、校验还是导出，并保留可用的已有结果。系统绝不能声称已完成实际上未完成的分析或导出。
- 原始上传文件和可识别 EXIF 在处理完成或临时会话过期后删除；保存原始图、参考图或个人偏好数据不属于 MVP。

## Testing Decisions

- 在端到端参数计划缝隙测试可观察的外部行为，而非测试模型提示词或实现细节。
- 使用明暗和色彩差异可控的已知样图对，验证建议方向、参数范围、顺序、解释和警告。
- 覆盖 RAW、JPEG、低光、强反差/逆光、人像、风景和明显不匹配的 A/B 图片对。所有情形都必须给出受限且可解释的输出，或明确报告限制。
- 验证无效、不支持、过大和无法解码的输入会产生可恢复的用户提示。
- 验证可选 XMP 分支仅对已校验计划可用，根据展示的值生成结构正确的预设，省略排除的目标专属设置，并且失败时不影响参数卡流程。
- 验证同一会话微调使用上一轮计划和新的 JPG 预览，返回新的受限计划，且不创建持久化账户或偏好数据。
- 验证处理与会话清理会依据临时会话策略删除原始上传文件和可识别 EXIF。

## Out of Scope

- 邮箱登录、账户、项目历史、已保存报告、长期任务存储和用户主动删除流程。
- 全局或场景偏好档案、偏好学习、从反馈生成偏好、偏好版本和偏好影响对比。
- 长期个人风格训练或任何跨任务个性化。
- 自动生成、修改或替换用户的最终照片。
- 批量处理、多张参考图、参考图混合、网页或社媒 URL 导入、自动抓图和社媒账户登录。
- 局部蒙版、裁切、镜头校正、修复和其他目标专属 XMP 设置。
- 非 Lightroom 编辑器（包括醒图映射）的一对一参数等价关系。

## Further Notes

- 核心成功信号是用户能理解并应用参数计划，让 B 向 A 中可迁移的视觉特征靠近。
- XMP 仍是 MVP 的验收要求，但它是用户明确选择的导出路径，不是主要成功路径，也不能成为手动调整的前提。
- 产品必须如实说明素材限制：调色无法完整复刻不同的构图、主体、光线方向或缺失的动态范围。
- 截至 2026-08-19，匿名独立上传、手动确认分析、临时任务、确定性图像测量、千问语义识图、安全 Lightroom 参数计划和正式结果页已实现；XMP、二次微调和到期清理仍待实现。最终阶段快照见 `archive.md`。
