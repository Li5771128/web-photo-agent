# 结果页视觉与章节导航调整

Status: approved

## 目标

让分析结果页与 RefTone 现有浅色工作台风格一致，并让长结果页可以快速定位到四个核心章节。此次只调整结果页的信息层级、视觉表达和页内导航，不改变分析数据、任务状态或接口。

## 结论卡与匹配可行性

- 将当前深色结果结论卡改为白色背景，使用现有主文字、辅助文字、细边框和轻阴影，与工作台容器融合。
- 风格名称和摘要仍位于结果顶部，图片 A/B 预览仍紧随其后。
- 匹配可行性采用 `design/mvp-flow-workbench.html` 的表达：同一行展示“匹配可行度”和“偏低 / 中等 / 较高 · N%”，下方显示长度等于分数的进度条。
- 低、中、高分别使用红、橙、绿单色系渐变；同一条进度条不混用多个风险色系。
- 进度条使用真实 `feasibility.score`，不引入原型中的随机演示逻辑。

## 结果章节顺序

结果正文按用户从结论到执行、再到证据复核的顺序排列：

1. A/B 差异方向
2. Lightroom 参数计划
3. 迁移边界与内容风险
4. 确定性图像读数

风格结论和 A/B 图片预览属于结果页总览，不纳入章节导航。

## 页内导航

- 宽屏在结果内容右侧空白区域显示吸附式章节目录，不压缩现有正文宽度。
- 目录包含上述四个章节；点击后滚动到对应标题。
- 滚动页面时自动高亮当前章节，章节进入视口上部后更新活动项。
- 目录链接支持键盘聚焦，并通过 `aria-current="location"` 表达当前章节。
- 在支持正常动效时使用平滑滚动；用户启用减少动态效果时使用即时定位。
- 页面宽度不足以容纳右侧目录时，将同一组导航移动到结果总览下方，显示为可横向滚动的吸附导航条。

## 实现边界

- 为四个结果区添加稳定的 section id，并通过一个数据驱动的导航组件生成链接。
- 章节观察仅在客户端运行，使用浏览器原生 IntersectionObserver；不增加第三方依赖。
- 未生成 Lightroom 计划时，导航中的参数计划仍定位到“参数计划尚未完成”占位区。
- 保持现有响应式网格、结果内容、API 数据结构和错误处理不变。

## 验证

- 前端生产构建与 TypeScript 检查通过。
- 增加或调整前端测试，验证章节定义、顺序和导航目标一致。
- 宽屏检查右侧吸附目录、点击定位及滚动高亮。
- 窄屏检查横向导航、键盘焦点和内容不溢出。
- 检查低、中、高三档分数的文字、颜色和进度长度。
