# Lightroom 规划对象与方向安全

Status: approved

## 问题

规划模型可能把参考图 A 当成需要修复的图片。任务 `c1844c09` 中，A 的平均亮度为 0.295，B 为 0.422；目标图 B 若向较暗的 A 靠近，曝光应降低，但模型给出正曝光，并以恢复 A 的黑位细节为理由。本地校验只收紧数值范围，没有拒绝相反方向。

## 规划契约 v2

- 参考图 A 是不可修改的风格来源。
- 目标图 B 是唯一应用 Lightroom 参数的图片。
- 规划不得修复或优化 A 的曝光、裁切、色偏等缺陷；A 的缺陷只能作为匹配边界或风险。
- `comparison.delta` 的定义是 `reference_A - target_B`。
- 对具有单调方向的指标，`increase` 表示应提高 B，`decrease` 表示应降低 B，`similar` 表示不应仅因该指标进行显著调整。
- 参数理由、预期效果、风险和停止条件必须描述对 B 的操作。

上述契约同时写入规划 Prompt 和 `input_context.objective`，避免模型只依赖字段名猜测 A/B 角色。规划 Prompt 版本从 `1` 升级为 `2`。

## 本地方向保护

本阶段只对映射明确的曝光参数增加确定性保护，避免对高光、阴影、黑白场等存在耦合关系的参数做过度推断：

- 使用 `comparison.median_luminance.delta` 判断 B 向 A 靠近的曝光方向。
- 当亮度差异方向为 `decrease` 且曝光建议大于 `+0.05 EV` 时，拒绝草案。
- 当亮度差异方向为 `increase` 且曝光建议小于 `-0.05 EV` 时，拒绝草案。
- 当亮度方向为 `similar`、草案未包含曝光，或曝光位于 `-0.05 EV` 至 `+0.05 EV` 时，不触发方向拒绝。
- 校验器不得自动翻转数值，因为同一草案的理由和其他参数可能仍在调整 A。

方向错误沿用现有 `plan_validation_failed`：保留确定性测量和识图结果，允许用户重新生成参数计划。

## 回归验证

- Prompt 与规划请求测试必须证明 A 不可编辑、B 是唯一调整对象、差异公式为 `A - B`。
- 规划上下文测试必须证明 `objective` 中包含相同的角色与方向语义。
- 复现样例 `A=0.295、B=0.422`：正曝光必须被拒绝，负曝光必须通过。
- 增加反向样例：A 明显比 B 亮时，负曝光必须被拒绝，正曝光必须通过。
- 现有参数范围、裁切、肤色、持久化和重试测试必须继续通过。

## 非目标

- 不自动修改或迁移数据库中已经生成的旧计划。
- 不在本阶段为所有 Lightroom 参数建立图像效果模拟器。
- 不根据自由文本理由判断方向；安全结论只依赖结构化测量和参数值。
