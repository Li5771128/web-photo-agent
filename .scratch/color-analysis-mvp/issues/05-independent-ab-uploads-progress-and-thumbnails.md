# 05 — A/B 独立异步上传、进度与缩略图

Status: ready-for-human

Archive: partial — 功能验收 10/12，剩余浏览器自动化与真实大文件/RAW 人工验证。

## Problem

当前上传交互把参考图 A 与目标图 B 绑定在同一次提交中。上传 A 时整个上传区域进入等待状态，用户必须等 A 完成后才能操作 B；上传完成后页面也没有保留缩略图，无法确认任务使用了哪两张图片。

## Desired Interaction

- 参考图 A 与目标图 B 是两个互不阻塞的上传通道。
- 用户提交 A 后，只禁用 A 自己的选择/提交控件；B 的控件仍可选择并立即开始上传。
- A 与 B 可以同时上传，各自维护独立状态和真实上传百分比。
- 每个上传中的文件至少每 3 秒刷新一次当前传输百分比；浏览器有更及时的真实进度事件时可以更频繁更新。
- 百分比只表示客户端到服务器的文件上传进度。服务器校验、排队及 AI 图片内容理解只显示文字阶段状态，不显示或模拟百分比。
- A、B 都上传并经服务器确认后显示“确认分析”；只有用户核对图片并点击后，系统才推进分析任务。
- 选择图片后立即显示对应本地缩略图；上传成功以及 AI 处理期间继续保留。

## Acceptance Criteria

- [x] A、B 各自具有独立的选择、提交、上传中、上传成功和上传失败状态。
- [x] A 上传期间仅影响 A 的上传状态，B 仍可选择并提交；B 上传期间亦同理。
- [x] A、B 同时上传时互不取消、覆盖或串行等待，并分别显示自己的进度条和百分比。
- [x] 上传百分比来自实际已发送字节数，不使用定时器模拟增长；进度展示至少每 3 秒保持可见并刷新最新真实值。
- [x] 任一图片上传失败只影响该图片通道；另一图片的选择、上传结果和缩略图不丢失。
- [x] 单张上传达到 100% 后显示“服务器确认中”，待服务器确认后显示“上传成功”，避免把客户端发送完毕误报为服务端已保存。
- [x] 只有 A、B 均被服务器确认且用户点击“确认分析”后才进入队列和 AI 图片内容理解；该阶段仅展示 `排队中`、`图片内容理解中`、`已完成` 或明确错误，不展示百分比。
- [x] 选择 A 或 B 后立即显示对应缩略图与文件名；RAW 使用明确占位提示并在服务端解码后显示预览。
- [x] 替换某一图片只更新对应通道及缩略图，不影响另一张图片；不再使用的本地 Object URL 会被释放。
- [x] 页面不因任一上传发生整页刷新或主线程阻塞；已有说明、另一上传通道和已完成结果仍可操作或查看。
- [ ] 自动化测试覆盖 A 上传时操作 B、B 上传时操作 A、A/B 并行上传、单侧失败重试、独立进度、双侧完成后入队、缩略图替换与 Object URL 清理。
- [ ] 手动验证包含两张接近大小上限的图片及浏览器网络限速场景。

## Implementation Notes

- 当前 `POST /api/tasks` 一次接收 A/B 两张图片，无法支持真正独立的上传生命周期。实现时应先建立临时任务或上传会话，再为 A、B 分别提供上传/确认接口；服务端必须保证会话归属、角色唯一性、替换语义及幂等性。
- 两个文件都确认可用后，由“确认分析”接口通过数据库事务和条件更新保证只入队一次，不能因双击或并发请求重复创建分析作业。
- 当前浏览器 `fetch(..., { body: FormData })` 没有通用的上传进度回调。可使用支持 `upload.onprogress` 的 `XMLHttpRequest`，或采用能够提供真实已发送字节数的等价传输方案。
- 缩略图优先使用 `URL.createObjectURL(file)` 本地展示，不需要公开 MinIO 对象地址或额外上传副本。
- AI 图片内容理解仍由 Redis/Worker 异步执行。本需求只要求该阶段展示状态文案，明确不提供处理百分比。

## File Limits and RAW

- 参考图 A 支持 JPG、JPEG、PNG、WebP，最大 30 MB。
- 目标图 B 的 JPG、JPEG、PNG、WebP 最大 30 MB。
- 目标图 B 额外支持 DNG、CR2、CR3、NEF、ARW、RAF、RW2、ORF，RAW 最大 40 MB。
- RAW 选择后先显示格式、文件名、进度与提示：“RAW 文件需上传后生成预览，上传期间暂不显示缩略图。”服务端解码完成后替换为无 EXIF JPEG 缩略图。
- 用户可在任何阶段只更换 A 或 B。AI 已开始时需确认取消当前分析；新任务复用未更换资产，只上传被替换的一侧。
- “重新开始”中止 A/B 未完成上传并取消旧任务；已经发出的模型请求可以结束，但结果必须丢弃。

完整设计见 `docs/superpowers/specs/2026-08-18-independent-upload-and-raw-design.md`。

- A、B 上传进度相互独立，百分比仅用于文件上传。

- 上传成功后需要显示并保留 A/B 缩略图。

### 2026-08-18 — 交互与 RAW 范围确认

- 选择文件后自动开始上传。
- AI 开始后仍允许单独更换一张图片；确认后取消旧分析，新任务复用另一张图片。
- 重新开始会中止当前上传并取消旧任务，迟到模型结果不得写回。
- 普通图片上限调整为 30 MB；目标图 B 支持首批八种 RAW 格式，RAW 上限为 40 MB。

### 2026-08-18 — 当前实现

- 已实现空任务、按角色上传槽位和服务端签发的上传尝试 ID；旧请求迟到时不能覆盖新文件。
- A/B 独立 XHR 自动上传并显示真实传输百分比；3 秒无新字节时保留真实值并显示仍在上传。
- A/B 原子确认后只允许一次入队；取消任务和 Worker 完成写入均有状态条件，迟到模型结果不会恢复已取消任务。
- AI 阶段可单独换图，新任务复制未更换资产并只上传替换侧。
- Worker 已接入 rawpy 0.27.0，RAW 使用占位提示并在服务端生成无 EXIF JPEG 预览。
- Docker Web/Worker 构建、12 项 Worker 单元测试及独立上传/单侧替换冒烟脚本已通过。
