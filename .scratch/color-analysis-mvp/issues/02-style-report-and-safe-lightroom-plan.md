# 02 — 参考风格报告与安全 Lightroom 参数计划

**What to build:** 对已上传的有效 A/B 图片对，用户可获得参考图风格报告、A/B 匹配可行度和可手动执行的 Lightroom 参数计划。计划按基础校正、风格塑形、可选微调排序，并以受校验的参数卡展示建议、解释与风险。

**Blocked by:** 01 — 匿名 A/B 调色任务与上传校验。

**Status:** ready-for-human

- [x] 报告展示参考图的风格摘要、主色/色彩倾向、明暗分布、对比度与饱和度，并区分可迁移与不可迁移特征。
- [x] 输出 A/B 匹配可行度和限制说明；素材不匹配时不伪装为可精确复刻。
- [x] 每张参数卡包含 Lightroom 面板、参数、推荐值或范围、理由、预期效果和风险，并按既定编辑顺序展示。
- [x] 参数在展示前经过格式相关的安全校验；面对裁切、肤色风险或 JPEG 等有限调整空间时收紧建议或解释限制。
- [x] RAW 可使用可用的 EXIF 与动态范围线索；其他已输出图片不假设存在可恢复的原始数据。

## Comments

### 2026-08-18 — 已完成的前置能力

- 已接入 `qwen3.7-max` 语义视觉识别，输出 A/B 场景、主体、人物与肤色提示、光线、可迁移特征、不可迁移特征、匹配限制和规划风险。
- 发给千问的是内存中生成的 1024px、JPEG 质量 80、无 EXIF 预览；请求设置 `store: false`，原始分辨率文件不发送给模型。
- 模型输出经过本地 JSON 字段校验后写入 `vision_analyses`，页面可展示识图报告；缺少 Key、预处理失败、服务失败和无效响应有独立错误码。
- 上述内容只是本 issue 的语义上下文前置能力，尚不能勾选现有验收项：主色、直方图、明暗、对比度、饱和度和 A/B 数值差异尚未测量；匹配可行度尚未形成完整评估；Lightroom 参数计划、数值边界校验和 RAW 线索均未实现。

### 2026-08-19 — 确定性测量阶段完成

- 新增 Schema v1 测量引擎，本地计算 A/B 的亮度分位数、明暗与裁切占比、对比度、HSL 饱和度、12 区间色相、主色、冷暖/绿洋红倾向和边缘活动度。
- RAW 使用固定 rawpy sRGB 后处理并只保存位深、黑位和白位等非识别性线索；不保存 GPS、相机序列号、作者等 EXIF。
- A/B comparison 统一使用 `reference - target`，输出数值差与 `increase`、`decrease`、`similar` 方向。
- `image_measurements` 原子保存 reference、target、comparison，任务 API 返回 Schema v1 结果。测量先于千问，即使缺 Key 或服务失败，已完成测量仍保留。
- 24 项 Worker 单元测试、数据库迁移、Web/Worker 构建和无千问测量冒烟均通过。
- 本阶段按用户确认不展示具体测量值，因此现有五项面向用户的最终验收仍保持未勾选。下一步是将测量与语义结果组合为规划上下文并实现受校验参数计划。

### 2026-08-19 — 结果页与安全参数计划完成

- 新增单页三阶段工作流和正式结果页，默认展示 A/B 预览、全部确定性读数、主色、A/B 差异方向、内容迁移边界和风险。
- Measurement Schema 升级到 v2，为 A/B 分别计算 32-bin 真实 RGB 直方图；历史 v1 仍可读取并明确提示缺少直方图。
- 新增第二次千问文本调用，只接收清洗后的测量、比较、非识别性 RAW 动态范围线索和已验证语义 JSON，不接收图片、EXIF、对象路径或存储地址。
- 参数草案经本地白名单、8–12 项数量、格式、RAW/JPEG 范围、裁切和肤色风险规则校验；最终卡片包含 Lightroom 面板、起始值、安全范围、理由、效果、风险与停止条件。
- 可行度由本地确定性差异和版本化语义扣分规则计算，模型不能自行决定最终分数。
- 新增 `planning → validating → ready` 状态、`lightroom_plans` 持久化和只重试规划的队列任务；失败时保留测量与识图结果。
- 36 项 Worker 单元测试、Web 生产构建/TypeScript、Worker 镜像、数据库迁移和无付费 API 的测量冒烟通过；真实千问双调用效果留待人工验收。

### 2026-08-19 — 真实图片联调缺陷修复

- 使用桌面 `test1.jpg` / `test2.jpg` 复现结果页崩溃：comparison 的 `schema_version` 元字段被当成差异项调用 `delta.toFixed()`；新增结果数据适配层和回归测试，只渲染合法差异项。
- `qwen3.7-plus` 的规划调用默认使用高强度思考，三次 60 秒超时；规划请求改为 `reasoning.effort: none`，真实调用约 25 秒返回。
- 修正校验顺序：先用 RAW/JPEG 基础范围识别异常值，再按裁切与肤色风险收紧并记录钳制；真实任务最终进入 `ready`，生成 12 项安全参数，1 项被风险规则收紧。
- Compose 迁移新增 `schema_migrations` 台账，避免每次重启重复运行旧状态约束；在已有 `planning` 数据时连续两次启动均成功。
- Web 回归测试、Web 生产构建/TypeScript、36 项 Worker 测试和真实 DashScope 规划调用均通过。
